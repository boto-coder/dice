# Dice Roller

A 3D physics dice roller for tabletop RPGs and board games. See [REQUIREMENTS.md](REQUIREMENTS.md).

**Use it:** https://boto-coder.github.io/dice/ (works offline after the first visit, and can be
added to a phone's home screen).

## Setup

```sh
npm install
npx playwright install chromium   # first time only, for e2e tests
```

## Commands

| Command                 | What it does                                                                      |
| ----------------------- | --------------------------------------------------------------------------------- |
| `npm run dev`           | Start the dev server at http://localhost:5173                                     |
| `npm run build`         | Type-check and build to `dist/`                                                   |
| `npm run preview`       | Serve the production build at http://localhost:4173                               |
| `npm test`              | Full suite: typecheck, lint, format check, unit, fairness and e2e tests           |
| `npm run test:unit`     | Vitest unit/DOM tests with coverage                                               |
| `npm run test:fairness` | Seeded physics fairness tests (chi-square per die, ~40 s)                         |
| `npm run fairness`      | Long fairness run with real randomness; writes `docs/fairness-report.md` (~4 min) |
| `npm run test:watch`    | Vitest in watch mode                                                              |
| `npm run test:e2e`      | Playwright end-to-end tests (desktop + mobile viewports)                          |
| `npm run test:firefox`  | The e2e tests in Firefox                                                          |
| `npm run lint`          | ESLint                                                                            |
| `npm run format`        | Format all files with Prettier                                                    |

## Offline use and installing

Production builds include a web app manifest and a service worker (generated by
`pwa/vitePlugin.ts`), so after the first visit the app works offline and can be
added to a phone's home screen. The dev server has no service worker.

Browsers only allow service workers on `localhost` or over HTTPS. To try it on a
phone, serve the build over HTTPS (or use `localhost` on the same device):

```sh
npm run build && npm run preview
```

The page has a Dark (default) / Light / System theme switch. Colours are CSS variables in
`src/style.css`; `index.html` applies the saved theme before the first paint.

Each die type, and each custom die, can have its own look (colour, pattern, finish and
number colour), chosen in the Appearance dialog or the custom-dice editor. Looks never change
results: rolls come from the physics and the face-reading only.

App icons are rendered from `public/icon.svg` with `node scripts/icons.mjs`.
Milestone screenshots are taken with `node scripts/screenshots.mjs` (see the
usage notes at the top of the script).

Frame rates while rolling 20 dice are measured with `node scripts/perf.mjs`
against `npm run preview` (results in `docs/performance.md`); add `--styled` to give
every die type a different look.

## Deployment

Every push to `master` on GitHub runs [the workflow](.github/workflows/deploy.yml): type check,
lint, format check, unit and fairness tests, then a build with `BASE_PATH=/dice/` that is
published to GitHub Pages (only `dist/`, not the rest of the repository). The browser (e2e) tests
don't run there, to keep deploys quick, so run `npm test` and `npm run test:firefox` locally
before pushing.

To try the Pages build locally: `BASE_PATH=/dice/ npm run build && BASE_PATH=/dice/ npm run preview`,
then open http://localhost:4173/dice/. `node scripts/livecheck.mjs` checks the live site (it
loads, rolls, works offline, and has a valid manifest) and takes screenshots of it.
